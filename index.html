Routines & Streaks Live app

A daily routines-and-streaks tracker: tasks on a daily cycle that resets at noon, persistent streaks and history, everything scoped to the signed-in person. It started as a way to keep my kids' daily routines on track — the engine turned out to be general, so now it tracks mine too. The whole app is a single HTML file backed by Firebase — and it was generated, not hand-written.

The interesting part is how it was built: a full specification and a library of prompts live in the same repo — the master design spec, the generator prompt that produces the code, the build prompt, and the phase plan. Change the prompt, regenerate the app.

  • The whole app is a build artifact: fix the prompt, regenerate, and the code follows.
  • Its day resets at noon, not midnight — the cycle follows real life, not the clock.
  • Streaks and history live in the cloud database, so they survive a new phone or a cleared browser.

AIMF — AI Messaging Format Protocol

An open protocol that lets AI assistants exchange structured messages — notes, file drops, requests, status reports — over ordinary email, with sender verification, consent agreements between the humans behind them, and versioned updates that every participant has to acknowledge.

Designed, tested, and run live between two different AI assistants in October 2026: the spec carries test vectors a bot can grade itself against, a trial prompt any assistant can be onboarded with, and a public registry of agreements. The canonical home is the repo — if it isn't on GitHub, it isn't an update.

  • Ships with test vectors a bot can grade itself against before claiming it speaks the protocol.
  • Consent is explicit: nothing beyond simple notes flows until the humans record an agreement, with a level and an expiry.
  • Updates are versioned and must be acknowledged — silence never counts as agreement.

Family Cards Live demo

Per-kid schedule cards for kids who won't use a calendar — each kid gets one simple page covering the next two weeks, framed as With Dad vs With Mom. Her events come first, non-school events are highlighted as Big, and a pickup or drop-off shows only when Dad drives — she assumes Mom otherwise. Nothing to install, no account, no invite spam: just one link that works.

The demo below is the public twin of a private family system: same page, same gate, same generator, running on fully invented kids (Emma and Noah) and invented events. The calendars stay private on the assistant side — a generator there reads them and writes one small JSON file per kid, and the page only renders that file. No calendar credential ever lives on the web host. Access is an expiring code, not an account: only its hash is stored, and a signed cookie does the rest. Each kid's card also carries a notes box — "Anything on your side?" — so she can tell Dad about plans the calendar doesn't know.

  • It meets kids where they are: no calendar, no account — one card, framed With Dad / With Mom, with Dad's legs shown and Mom's simply assumed.
  • Exceptions get exactly one word — CHANGED: a third-party pickup names the driver, a moved time shows the new time only, no explanations.
  • Codes, not accounts: expiring links whose SHA-256 hashes are all the host stores, a signed scoped cookie per kid, and a gate that fails closed.

Automations

The unglamorous systems that do the daily work. Each one was designed around a simple rule: it should run quietly, explain itself when it acts, and never guess when it can ask. Each card's prompt is a complete, self-contained brief — copy it, paste it into an AI assistant that can see your calendar, and it can build the same system for you. Under each summary sit the highlights: the clever bits and hard-won lessons drawn from the full spec. Built by Andrew Horowitz with Muse, Meta's personal AI agent — it runs most of the automations above and maintains this page. The specs and prompts are linked on every project, judge for yourself.

🚗 The self-maintaining calendar

Every morning, a scanner reads the next seven days of the calendar and adds private drive-time blocks before in-person events — mapped drive × 1.2 + a cushion, chained from home or the previous stop, with get-ready blocks, pickup routing for family events, and a plain-English note in each block explaining how the route was deduced. Tight gaps get a warning pin; ambiguous driving duties get batched into one confirmation list instead of a guess.

  • Every block is stamped with its event's ID, so the scanner recognizes its own blocks — duplicates are checked before every insert and swept after every run.
  • For school pickups it deduces where a kid actually is — still at school, or back at the home base — and writes the reasoning into the block.
  • Ambiguous driving duties are never guessed: they collect into one batched confirmation list, asked once.

⏰ Time-to-leave alerts, with a light show

Every 15 minutes, the next trip is checked against live traffic from the current GPS position. When it's time to go: one ping — and if I'm home, all five smart lights run a prism show at full brightness, then restore themselves three minutes later. If I leave and stay away, the house turns its own lights off.

  • One alert per trip, ever — a transition that already fired never pings again.
  • A location reading older than 30 minutes counts as "unknown" and the system does nothing; stale GPS once turned the lights off while I was home.
  • The light show snapshots the lights first and restores them on a 3-minute timer — with a second job as backstop if the timer is missed.

⛽ Gas tracker

I report the gauge needle; fill-ups reconstruct themselves from the settled charges on my card. The system estimates miles driven from the calendar, projects the day the tank crosses a quarter, and pins a "get gas" stop onto a trip I'm already making — at the best-priced convenient station on that route, never slipping an arrival time to do it.

  • Fill-ups are reconstructed from the settled charge on the card — never the $175 authorization hold a pump places.
  • The stop is added time, not taken from the drive: the travel block grows earlier so the arrival never slips.
  • If another drive that day passes a station at least 10¢/gal cheaper, the stop moves to that drive instead.

🎺 Band schedule monitor

A daily diff of a high-school marching band's weekly schedule document, plus coordinator emails and crew texts. Changes surface the same morning; on performance days the brief leads with the call time (not the show time) and the crew sign-up link.

  • It diffs the source schedule document itself, so a silent edit surfaces the same morning.
  • Schedules lead with the checkpoint time — when the crew must arrive — with performance time alongside, never the other way round.
  • Tentative dates stay visibly tentative: a placeholder is never treated as a firm conflict.

🗂️ PARA + GTD filing system

Every new document lands in a PARA folder structure in Drive; every task lives in exactly one GTD list and carries links back to its project resources, so a task and its paperwork are always one search apart. A weekly review task generates itself every Friday.

  • Every task lives in exactly one list — a project list if it has one. Never two homes.
  • Tasks carry links to their project files, and every project folder links back to its task list — one search from either side finds both.
  • The weekly review task creates itself every Friday; nothing depends on remembering it.

📬 Priority comms watch

Every 15 minutes during waking hours, texts, email, and call logs are checked for one priority contact, so a time-sensitive family request never sits unseen. Everything else batches into a single morning list — no drips.

  • Checks texts, email, and the call log every 15 minutes from 7 AM to 10 PM — and surfaces anything from the priority contact immediately, in full.
  • It knows its evidence limits: phone message stores can lag hours, so anything seen only in a notification is labeled as exactly that.
  • Everything else waits for the morning batch by design — one list, no drip of notifications.

🧹 Inbox hygiene

School digest and notification mail is auto-labeled and swept out of the inbox daily; anything stale past five days trashes itself. The inbox stays for things that need a human.

  • Nothing is ever permanently deleted — trashed mail stays recoverable for 30 days.
  • Only an approved list of digest senders is touched; everything else stays exactly where it was.
  • School mail is labeled and archived the day it arrives, so reports never pile up in the inbox.

🌅 Morning day-plan

One consolidated brief to start the day: today's drives and tight spots, tasks due, replies owed, and anything that changed overnight — assembled from the same systems above.

  • Collisions and hard deadlines come first, before the day's schedule — the brief leads with what needs a decision.
  • Replies owed are listed with how long each person has been waiting.
  • It may suggest one inbox cleanup, with a count from real mail — but never applies one without an explicit yes.

How these get built

Spec first, prompt as source, verify by reading back

  1. Write the spec — behavior, edge cases, and what "done" means — before any code.
  2. Keep the prompts in the repo next to the output they generate; a fix starts as a prompt edit.
  3. Generate, then verify by reading the result back from where it actually lives.
  4. Track every known issue in the open, in the repo, with a status log anyone can audit.
  5. Automate the boring verification too — the systems watch themselves and report changes.
